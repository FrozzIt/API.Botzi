# Краткий клиентский контракт ProxyAPI v1

Статус: **черновик для отдельной PM-приёмки и G0**. Scope согласован архитектором, но задача 0.5 и G0 ещё не приняты.

## Объём

Реестр содержит ровно 64 операции method+path:

- `v1` (52): `A01–A02`, `P01–P04`, `P09–P14`, `C01–C07`, `C09–C12`, `V01–V04`, `L01–L09`, `L12–L21`, `T02–T03`, `M01–M04`;
- `deferred` (12): `P05–P08`, `C08`, `L10`, `L11`, `L22`, `S01`, `T01`, `T04`, `T05`.

Доставка callback также deferred, но не является отдельной операцией реестра и не входит в число 64. Полный список method+path и состояние доказательств приведены в [матрице совместимости](compatibility-matrix.md); машинный черновик — в [OpenAPI](openapi.yaml).

Статус `v1` означает продуктовый scope, а не доказательство полной схемы LPTracker. DOC/LIVE-факты и отмеченные неопределённости сохраняются в матрице; непроверенные поля и envelopes не считаются подтверждёнными.

## Авторизация и изоляция

Клиент использует только credentials и token ProxyAPI. LPTracker credentials и token клиенту не выдаются. Разрешённый проект определяется серверным конфигом клиента; переданный `project_id` только сверяется с назначением.

Объект выдаётся или изменяется только после доказанной связи с разрешённым проектом. В частности:

- C05 проверяет проект до удаления; каскадные эффекты проверяются отдельно;
- C06–C07 разрешены только при доверенной серверной связи `detail → contact → project` и повторной проверке родителя; без доказанной связи ProxyAPI нейтрально отказывает до upstream-вызова;
- L01/L06 не принимают неподтверждённых `owner` или `observers`;
- T02–T03 проверяют проект и очищают вложенные staff fields;
- L21 выдаёт записи только через безопасный домен ProxyAPI: прямой upstream URL клиенту не возвращается.

## Контракт deferred

После успешной локальной авторизации каждая deferred-операция возвращает:

- HTTP `200`;
- `Content-Type: application/json`;
- JSON `status: "error"`;
- application code `501`;
- сообщение `Operation is not available in this release`.

Пример:

```json
{
  "status": "error",
  "errors": [
    {
      "code": 501,
      "message": "Operation is not available in this release"
    }
  ]
}
```

Перед таким ответом ProxyAPI не проверяет существование объекта, не вызывает LPTracker и не запускает внутренний login. Ошибка локальной авторизации обрабатывается раньше и не раскрывает release status маршрута.

## Ошибки и открытые решения

Формат deferred `501` выше входит в согласованный пакет. Application-коды `400/404` для остальных отказов ещё не утверждены и не должны представляться как принятый контракт. Текущая framework-валидация использует application `422`; выбор между `400` и `422` остаётся вопросом PM/G0.

Timeout после отправки изменяющей операции не подтверждает её неуспех и не разрешает автоматический повтор. Точные коды provider/quota/unknown outcome фиксируются до реализации соответствующих записей.

## Критерий готовности

Для G7 требуются contract-тесты success/error/isolation/fields всех 52 операций v1 и тесты одинакового neutral refusal всех 12 deferred с доказанным отсутствием object lookup, LPTracker-вызова и внутреннего login. Доставка callback не считается реализованной. Отдельная PM-приёмка 0.5 и отдельный `G0 APPROVED` обязательны до перехода по процессу.
